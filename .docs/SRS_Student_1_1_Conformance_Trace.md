# Student 1.1 conformance trace: BASE foundations, ingestion and scientific boundaries

Review date: 2026-10-08. Status: source-and-evidence trace for review, not release certification or Council ratification. The current working tree is being completed; this document does not assign a final 1.1 suite count or silently transfer historical acceptance to changed source.

The baseline is the full [Chunk 17 architecture](SRS_Chunk_17_CoChem_BASE_Architecture.md), the full [BASE architectural proposal](SRS_Chunk_Proposal_CoChem_BASE_Architectural_Review.md), the [Task 1 subsystem specification](task1_subsystems_architectural_specification.md), and [Task 1 WBS v2.2.0](task1_level2_wbs_breakdown.md). The two specifications reuse REQ-BASE-001 through REQ-BASE-016 for different obligations. Their rows below are deliberately separate. Coverage is **16 Chunk 17 requirements + 16 proposal requirements + 24 WBS items + 8 verification criteria + 17 Task 1 L3 microtasks = 81 mapped obligations**. Mapping coverage does not mean 81 accepted obligations.

The user-authorized scope is BASE-owned setup, input validation, GUI, native execution integration and truthful downstream handoff. Students supply their own starting monomer or complex geometry. A native Hessian is not a setup or ordinary geometry-ingestion prerequisite; it is required only by the particular READ/reanalysis operation that consumes it. ORCA and CFOUR are optional, strongly recommended engines: absence disables their dependent operations while BASE and available free engines remain usable. Unsupported scientific operations must retain an explicit unavailable status. See [scope boundaries](BASE_Alpha_Scope.md), [student workflow](Student_Research_No_Code.md), and [actual deployment acceptance](Student_Deployment_Pilot.md).

Every table row has a bounded status and a remaining acceptance limit. **Local** means a retained actual local execution or native replay supports the stated behavior. **Mapped** means current source and meaningful tests are identified, without claiming a fresh run of every referenced test. **Validation pending** identifies an implemented route whose stated scientific/platform threshold lacks full acceptance. **Provider unavailable** identifies downstream science that BASE cannot truthfully advertise. **Implementation gap** identifies a concrete missing software behavior. **Delivery governance** identifies project artifacts, owner allocation or independent review rather than student chemistry functionality. These categories are not interchangeable. Evidence identifiers E01–E23 refer to the catalog at the end. Test files are entry points to inspect, not an assertion that every node in them passed in this review.
